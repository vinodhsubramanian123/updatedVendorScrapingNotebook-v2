# Catalog evidence, replay, and learning

Use these checks when changing OCA capture, product catalog queries, learned rules, or BOQ export. See [the implementation plan](audits/2026-11-20-remaining-catalog-code-gaps-plan.md), [runtime discovery](RUNTIME_CONDITIONAL_DISCOVERY.md), and [invariants INV-259 through INV-268](INVARIANTS.md#catalog-evidence-and-learning-release-boundaries-2026-11-21).

| Workflow | Required evidence | Regression to replay |
| --- | --- | --- |
| Product and customer scope | Resolve explicit models and generations before searching, including `Alletra 10k`, `Alletra MP B10000` (`B10100`/`B10200`), and `Alletra MP X10000`. Carry the same typed filters through execution and acceptance. Search, exact SKU lookup, dashboard, CLI, and MCP share scoped evidence and materialized `canonicalSpecs` (`INV-267`). | An unknown model cannot widen the search. GB, USD, TDP wattage, core count, and lead-time limits remain independent. GPU software/service SKUs (`E-RTU`) cannot appear in hardware GPU results. |
| Lifecycle and fulfillment | Keep visibility, selectability, compatibility, lifecycle, and orderability separate. Preserve base, owner, and selector provenance. Vendor supply status `CS` requires supply confirmation or an applicable replacement (`INV-265`). Preserve 6-character hardware localization suffixes (`R7R97A#AC3`) distinct from base chassis SKUs (`R7R97A`). | A hidden or unselectable row cannot meet an orderable filter. A supplier-constrained SKU (`[CS]`) cannot be overwritten by a default `Active` column or pass as an automatic alternative. `R7R97A#AC3` (`$0.00`) cannot collide with `R7R97A` (`$19,746.00`). |
| Flagship storage dual-source sizing (`Alletra_MP_B10000`, `Alletra_MP_X10000`) | Combine live HPE OCA catalog extraction with HPE Ninja Online sizing telemetry (`scripts/scrapers/capture_ninja_online_sizing.js`). Enforce Switchless `B10100` (`S0B84A`, up to 24 internal drives, 0–3 JBOFs, max 24/72 drives, no backend switches) vs. Switched `B10200` (`S1R06A`, 0 internal drives, 1–8 mandatory JBOFs, max 384 drives, mandatory backend NVMe-oF switches) mutual exclusion (`INV-266`). | Size core controller/JBOF/drive/capacity topology in Ninja Online, export OCA JSON, import into HPE OCA, and adapt transceivers (SFPs/QSFPs), cabling, support services (`Services -> Edit`), and CLIC validation in OCA. |
| Price and lead-time history | Use the exact SKU, including suffixes. An as-of price uses a verified observation on or before the date. Preserve null prices and delivery estimates. Load both hardware and service archives. Consolidate identical transitions only when catalog observation windows overlap. | A later capture cannot prove an earlier price. Hardware and service rows with different prices on the same day cannot create a drift. Portfolio follow-ups retain their earlier product and component scope. |
| Staging and promotion | Require a readable suite, completed applicable tests, an audited capture, and matching artifact hashes. Carry forward reports, evidence, and customer workbooks. Keep staged receipts on name collisions. Archive unreviewed legacy notes under `history/legacy_catalog_deltas.json`. | Missing or skipped tests cannot pass the gate. Promotion retains customer workbooks and keeps old catalog certification out of the active snapshot. See [the promotion regression](../tests/unit/test_post_hardening_boundary_review.js). |
| Learning and telemetry | Treat scoped `catalog_deltas.json` as durable. Generated master registries follow the scoped and global durable sources. Reopen the full seed set after writing. Record the exact applied rule ID and effect in phase 4, separately from retrieval. Record repeated query misses by typed scope. Close a miss only after a verified promoted capture replays the original request. | Two workflow advisories with the same type both survive. A fresh process uses the later scoped rule, and an unrelated rule, recommendation, or proposed fix cannot supply application proof. An unrelated capture cannot close a miss. |
| Saved-run delivery | Bind new BOQ runs to the catalog, services, and rules revisions used for the evaluation. Keep the delivery fingerprint stable across serialization by signing the acceptance decision and its source evidence. The display projection can be regenerated. Re-read bound files before export and publication. Keep historical documents and their original evidence. | Sign, serialize, reopen, and export an unchanged run. Change a candidate quantity or a bound catalog input and verify that the export is denied. |

## Release evidence

- Run catalog unit and acceptance tests alongside the dashboard route tests. Replay each staged product before promotion, and run `node scripts/maintenance/audit_product_rules_association.js --portfolio-replay` for portfolio drift. Verify the exact number of cases and disclose unreadable sources and excluded evidence.
- Run the Solution Intelligence dev and held-out benchmark, export authorization tests, and promotion and recovery tests. Preserve a failing control for stale evidence, missing rules, and partial catalog coverage.
- Run `node scripts/maintenance/record_scraping_workflow_learnings.js` when changing the seed advisories. Reopen the [reachability receipt](../outputs/ProLiant/Gen12/DL380_Gen12/evidence/scraping_review/workflow_learning_reachability.json) and verify the complete set in a fresh process. Replaying one source does not provide independent corroboration.
- Inspect staged output and receipts before pushing to a shared repository. Publish validated product catalog artifacts and sanitized evidence. Keep credentials, SSO records, live browser endpoints, local working paths, and customer inputs out of public history.
- Use dated capture, cloud readback, and current exact-manifest CLIC receipts for their respective claims. A local release test certifies the behavior it executed.
- Check the required workbook views and SKU coverage against the exact artifacts committed for release. The 21 November refresh consolidated accessory and support tabs for DL380 Gen12, DL380a Gen12, and SY480 Gen12. Every SKU on the removed tabs still appeared in the refreshed workbooks. These profiles now require named, populated views alongside the existing SKU and category floors.
- Exercise explicit Alletra MP and server sizing requests with a different dashboard product selected. RFP sizing must preserve the named product. Alletra MP must report the Ninja Online handoff, distinguish the requested B10100/B10200 topology, and stop before generating a generic BOM. Confirm authenticated Ninja-to-OCA import and CLIC separately on the actual configuration.
- In browser release tests, await the request that owns the result and verify the visible result in its own panel or dialog. Let ordinary browser requests finish before an intentional restart or browser teardown. Keep disconnect tolerance confined to the planned restart window.
- Run synthetic dashboard reconciliation in read-only mode. The browser release test checks the reconciliation result and verifies that fixture discrepancies stay out of the product learning store.
- Check dashboard health endpoints with server offline mode enabled. NotebookLM and OCA browser status must return local standby without launching a NotebookLM CLI probe or reading the OCA browser session.
